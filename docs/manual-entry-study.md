# Measure manual-entry value before claiming it

**Status: no human-entry benefit is established by this repository's evidence.**
The current [workflow results](workflow-results.md) are synthetic selected cases.
Codec throughput, mutation detection and automated browser actions are not human
completion times or error rates. This protocol is a plan, not collected data.

## Compare the actual task

Use the same authorized record lookup and confirmation task for three routes:
the current identifier/search workflow, a simple alias, and RefMint. Preserve
existing identifiers and credentials. Use consented, non-sensitive records and
representative ID lengths; do not choose only nearby numbers that favor one route.
If the real workflow uses pasted links or QR codes, include it instead of assuming
that users must type. Keep manual entry and copy/paste results separate.

Predefine task order, practice, time limit, exclusion rules and the benefit/cost
criteria with the product owner before collecting results. Use different records
for each task and counterbalance route order across participants. State whether
the task is visual transcription, phone dictation or a real support task; do not
generalize one into another. A single-person synthetic pilot is exploratory only.

## Record outcomes without losing failures

Measure elapsed time from showing the task to the first query, first correct
lookup and final correct-record confirmation. Record first-query success, rejected
input, not-found, wrong-record lookup/confirmation, skipped tasks, timeouts and
interruptions. Keep practice separate. Do not equate delete-key counts with typo
counts: silent corrections before submission are only partly observed.

Retain every started trial and all protocol violations. Report participant/task
counts and completion rates next to time summaries. Report successful-trial median
times with their denominators and spread; do not make failures disappear from the
comparison or turn an aborted timer into a successful time. Separate search errors
from interruptions and unauthorized records. Avoid retaining entered private IDs
or raw keystrokes; use anonymous task identifiers and the minimum necessary data.

## Interpret conservatively

Compare paired routes within the same task conditions. Explain sample size, order
effects, participant experience, record length and any exclusions. Retain raw
consented observations privately and publish only approved aggregates and methods.
A small pilot can identify usability problems and guide a larger study; it cannot
establish a population-wide advantage or prove need in another application.

If the current ID or simple alias is faster, easier or sufficient, report that and
keep it. RefMint's own stability and its [integration costs](adoption.md) remain
separate questions. Do not publish invented human timings or label automated QA
as participant observations.
